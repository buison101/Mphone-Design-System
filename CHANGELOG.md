- **Settled the localization architecture in `docs/15` §4.7 and `AGENTS.md`: a keymap contract with substitution at build.** `i18n/keymap.json` binds one string position in vendor source — file, occurrence, source text — to one semantic message key, together with the context, routes, role and length budget a translator needs. A Vite plugin substitutes only the positions the keymap lists and never guesses, so the transform is deterministic and vendor files stay untouched on disk. Keys stay semantic rather than being the English sentence, which is the point: the same English word in two contexts gets two keys and can have two Vietnamese translations, something a global English-to-Vietnamese dictionary cannot express.
- **The upgrade path is now a report rather than a merge.** `i18n:diff` compares the keymap against any vendor tree and classifies every entry as matched, reworded, moved, or vanished. Translations attach to keys, not to edited files, so a vendor rewording is one line to review instead of a conflict in a file we had modified. Three rules protect this: never reformat vendor paths, keep the pristine tree of every vendor version (`.tools/mto-stage-20260902/full-version` for 4.2.0), and record every unavoidable vendor edit in `docs/vendor-patches.md` after first asking whether the change can be made a level higher — a MUI theme override instead of nineteen inline `textTransform` edits, for instance.
